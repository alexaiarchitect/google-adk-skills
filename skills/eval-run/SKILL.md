# Run ADK evaluations

The thing to know before anything else: **`adk eval` always exits 0.** It prints

```
Eval Run Summary
expense_claims:
  Tests passed: 3
  Tests failed: 1
```

and returns success. A CI step calling it directly passes forever. It also counts
`NOT_EVALUATED` in the failed column, so its own summary cannot distinguish a
regression from an unreachable judge. Everything here runs through a wrapper that
reads the result files and reports the three statuses separately. (Unreleased
`adk-python` main after 2.12.0 makes `adk eval` exit 1 on a failure; the
wrapper's exit code stays the authoritative one on every release.)

`${CLAUDE_SKILL_DIR}` is this skill's directory.

## Flow

1. **Discover.** Layout, runner, backend, criteria and their cost:

   ```bash
   python3 ${CLAUDE_SKILL_DIR}/../adk/scripts/check_env.py <agent-dir> --config <config>
   python3 ${CLAUDE_SKILL_DIR}/scripts/run_evals.py <agent-dir> --dry-run
   ```

   `--dry-run` prints the exact commands, before any credential check and
   without needing ADK installed.

2. **Report.** The runner it resolved, the config it will use (and any others it
   found), the metrics and their **cost tier**, and how many cases will run.
   When several evalsets or configs exist, ask which before running.

3. **Options and cost.** Before spending anything, say what it costs. A judge
   metric costs one model call per invocation per sample: 20 cases with 2 turns,
   two rubric metrics at 3 samples is about 240 judge calls, times `--runs`.
   Offer the cheap subset first.

4. **Confirm, run, hand off.** Then send the results to `/adk:eval-analyze`.

## Which command for which layout

**Recipes layout** — the config is never auto-discovered, so always pass it:

```bash
adk eval <project>/app <project>/tests/eval/evalsets/happy.evalset.json \
    --config_file_path <project>/tests/eval/eval_config.json
```

**Flat layout** — `test_config.json` beside a *single* evalset is found
automatically; with several evalsets, pass it explicitly:

```bash
adk eval <agent> <agent>/happy.test.json
```

Selected cases only: append them to the evalset path
(`happy.test.json:edge_frozen_cost_centre,edge_over_limit`).

## The honest gates

| Route | Gate | Use it |
|---|---|---|
| `scripts/run_evals.py` | real exit code from the result files | anywhere a result must gate something |
| `pytest` with `AgentEvaluator` | pytest's own code; `AgentEvaluator` raises | projects with `tests/eval/test_eval.py`; the only way to evaluate one sub-agent (`--agent-name`) |
| `scripts/run_registry.py` | one code for a batch of suites | several agents, or several tiers |
| `scripts/conformance.py test` | `adk conformance test` does raise | drift after a refactor |

Never `adk eval` alone in CI. A project with no pytest gate gets one from
`gen_test_eval.py`.

## Decision rules

- **Repeat runs with `--runs N`, not `num_runs`.** `AgentEvaluator(num_runs=N)`
  averages scores across runs, which hides the variance you are measuring.
  `--runs N` keeps each run's results separate so `/adk:eval-analyze` can compute
  pass@k.
- **An empty suite fails on 2.10+, and used to pass.** `AgentEvaluator.evaluate`
  and `evaluate_eval_set` raise `ValueError` when there are no eval cases, no
  `*.test.json` under the directory, or `num_runs < 1`. On 2.9.2 all three passed
  silently, so a gate that had lost its cases was green.
- **Efficiency values are not verdicts.** On 2.10+ every run also reports
  `tool_call_count_v1`, `inference_call_count_v1`, `token_usage_v1` and
  `invocation_duration_v1` as informational. They cannot be configured and they
  gate nothing; `/adk:eval-analyze` keeps them out of the pass/fail count.
- **`NOT_EVALUATED` is not a regression.** Default `--not-evaluated fail` in CI,
  because a suite that silently stops scoring is worse than one that fails. Use
  `warn` locally, where exit 3 means "inconclusive" rather than "broken".
- **Check the backend before spending.** Metrics scored by the Vertex evaluation
  service need `GOOGLE_API_KEY`, or a project and location with ADC; without
  either you get a page of never-scored cases.
- **A flat-turn legacy file cannot go through `adk eval`.** It crashes inside
  ADK; the wrapper refuses it and points at `migrate_legacy.py` or the pytest path.
- **Run the cheap tier first.** There is no point paying a judge to score an
  agent that called the wrong tool.
- **Resolve the runner honestly.** `$ADK_PYTHON`, a project venv, an `adk` on
  PATH, then `uv run --with "google-adk[eval]==2.12.*"`. If none works, say so and
  give the install command.
- **Recording conformance needs a running dev server** on 127.0.0.1:8000 started
  with the recordings plugin; the script checks the port and prints the command.

## Scripts

| Command | Does | Exit codes |
|---|---|---|
| `scripts/run_evals.py <agent-dir> [--evalset F] [--config F] [--cases a,b] [--runs N] [--detailed] [--storage gs://] [--not-evaluated fail\|warn] [--min-pass-rate P] [--dry-run]` | runs and gates; `--min-pass-rate` also fails a run whose pass rate is below `P` | 0 clean, 1 failures, 2 env, 3 only never-scored |
| `scripts/run_registry.py --registry F [--tier pr\|nightly] [--suite NAME]` / `--init [--root D] [--out F]` | batch of suites; `--init` builds the manifest by discovery and writes `"frozen": false` on each suite (the template marks `trajectory_pr` frozen, `judge_nightly` not); a frozen suite's cases are protected by `manage_cases.py` (`EVS120`) | 0 clean, 1 failures, 2 env |
| `scripts/run_pytest_eval.py <path> [-k EXPR] [--num-runs N] [--agent-name N] [--behavioral [--runs N] [--min-pass-rate P]]` | the pytest gate; without `--behavioral` it ignores `test_behaviors.py`; with it, it runs only that file, each behaviour `--runs` times (sets `ADK_EVAL_RUNS`), gated per behaviour on `--min-pass-rate` (sets `ADK_EVAL_MIN_PASS_RATE`, default 1.0); failing runs show as xfail and `test_pass_rates` is the gate | pytest's code, 2 for env |
| `scripts/gen_test_eval.py [path] [--out F] [--agent-name N] [--behavioral] [--dry-run]` | writes a pytest gate for an existing project; `--behavioral` writes `tests/eval/test_behaviors.py` instead (`run_turn`, `Turn`, three behaviours taken from the happy, edge and no-call cases) | 0, 1 refused, 2 usage |
| `scripts/conformance.py record <case-dir> [--mode none\|sse]` / `test [dirs] [--generate-report] [--skip-recordings-check]` | record and replay through the runner; `test --mode replay` refuses (`CNF020`) a case with no `generated-recordings.yaml`, because ADK skips those with a warning and can still exit 0; refuses a case with `input.yaml` / `test.yaml` and no `spec.yaml` (`CNF015`; the record `--help` names those but only `spec.yaml` is read) and the `bidi` mode ADK cannot record (`CNF021`) | 0, 1 failed, 2 env |

## Completion checklist

- [ ] The runner and ADK version were reported, not assumed.
- [ ] The cost tier was stated before anything was spent.
- [ ] The recipes layout, or any multi-evalset run, got an explicit `--config_file_path`.
- [ ] Failures and never-scored cases were reported separately.
- [ ] Result files were located and handed to `/adk:eval-analyze`.
- [ ] Nothing in CI relies on bare `adk eval`.
